# Governance

## Principles

- Scientific integrity
- Transparent decision-making
- African institutional capability
- Public value
- Technical accountability
- Community relevance
- Reproducible evidence
- Non-partisan operation

## Founding leadership

Dossiya Dakou is the founder, research lead and lead systems engineer of Africa Energy Dignity.

The founder maintains responsibility for:

- scientific direction;
- system architecture;
- engineering and coding standards;
- model-integrity requirements;
- repository-scope protection;
- release approval;
- contributor governance; and
- alignment with the project's Africa-centered mission.

Founder responsibility must not prevent transparent collaboration, technical review, contributor recognition or future governance evolution. Material scientific, architectural and release decisions remain reviewable through documented issues, pull requests and repository evidence.

## Decision classes

| Decision | Minimum review |
|---|---|
| Editorial documentation | One reviewer |
| Data transformation | Data reviewer |
| Scientific definition | Scientific and domain review |
| Mathematical model | Independent technical review |
| Country recommendation | Scientific, engineering and country-context review |
| Production release | Verification and validation approval |

## Institutional representation

Africa Energy Dignity is an independently developed open-source research and engineering initiative.

Participation in, study at or collaboration with a university, research institution, company or professional organization does not make AED an official institutional project unless formal authorization is documented publicly.

## Independence

The project may collaborate with governments, institutions and leaders, but it is not a political party, campaign or personality-centered movement.

## Research-release pathway

Scientifically meaningful AED milestones may be published as versioned GitHub releases.

After a validated release is approved:

1. Create a semantic GitHub release.
2. Archive the release through Zenodo.
3. Obtain a DOI.
4. Update `CITATION.cff`.
5. Add the DOI to ORCID.
6. Add the verified release to the CV, LinkedIn and professional portfolio.

Development commits and incomplete milestones must not be presented as formal research outputs.
