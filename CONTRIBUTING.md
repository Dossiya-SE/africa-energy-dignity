# Contributing

## Contribution standard

Contributions must be:

- Relevant to the approved project scope
- Reproducible
- Traceable to evidence
- Tested where code is involved
- Explicit about assumptions and limitations
- Respectful of data and software licenses

## Workflow

1. Open or select an issue.
2. Confirm scope and acceptance criteria.
3. Create a focused branch.
4. Make the smallest complete change.
5. Add or update tests and documentation.
6. Run the quality checks.
7. Submit a pull request linked to the issue.
8. Address scientific and technical review comments.

## Branch naming

- `research/...`
- `data/...`
- `model/...`
- `dashboard/...`
- `docs/...`
- `fix/...`

## Commit guidance

Use concise imperative messages, for example:

`Define energy-dignity evidence classes`
